# خطة مشروع مكتبة الطب

آخر تحديث: 2026-10-26

هذا المستودع مشروع مستقل عن مكتبة الهندسة الرقمية. الموجود حاليًا نموذج أولي بالواجهة والخادم، ويحتاج إعداد قاعدة البيانات والتخزين والنشر وتجربة الأجهزة قبل استخدامه في المكتبة.

## المتطلبات المثبتة

| المجال | القرار |
|---|---|
| المستودع | مشروع مستقل باسم medical-library |
| الطالب | يرفع الصور أو ملفات PDF، يحدد عدد النسخ والخدمة المطلوبة، ويرى حالة الطلب فقط |
| الموظف | يستلم الملفات، يتابع الطلبات ويحدّث حالتها، ويضيف المبيعات والمصروفات اليومية |
| المدير | يدير حسابات الموظفين، ويشاهد التفاصيل المالية وينشئ التقارير |
| الصور | تكرار صورة واحدة، أو توزيع صور لأشخاص مختلفين بأعداد نسخ مستقلة في الصفحة نفسها، مثل 5 صور لشخص و4 لشخص آخر |
| التخطيط | تخطيط مبدئي 3×3؛ مقاس الورقة وأبعاد الصور والهوامش تحتاج تحديدًا وتجربة |
| الطباعة | تُستخدم تسميات تسلسلية: طابعة 1 — Epson AM-C400 Series؛ طابعة 2 — iR-ADV 8585/8595؛ طابعة 3 — KONICA MINOLTA C554SeriesPCL؛ طابعة 4 — Canon الأبيض؛ طابعة 5 — Canon رصاصي. يلزم تطبيق التسميات في Windows والتحقق من اتصال Wi-Fi. |
| الهاتف | رفع الملفات من الجهاز؛ المشاركة من Telegram وWhatsApp تعتمد على إمكانات الهاتف والمتصفح |
| الاستضافة | Render عبر Blueprint باستخدام render.yaml؛ قاعدة البيانات والتخزين منفصلان عن مكتبة الهندسة |
| الملازم | مرحلة لاحقة: إضافة الأقسام والكليات والمراحل والملازم |
| الهوية | شعار الكلية سيضاف عند إرساله |
| الخصوصية | يبقى المستودعان عامّين أثناء التطوير، ثم يحوّلان إلى خاصّين بعد اكتمال العمل |

## الطابعات الظاهرة في Windows

**التسميات التسلسلية المقترحة للطابعات الفعلية:**

1. طابعة 1 — Epson AM-C400 Series (تظهر رسالة خطأ تعريف).
2. طابعة 2 — iR-ADV 8585/8595.
3. طابعة 3 — KONICA MINOLTA C554SeriesPCL (يظهر تنبيه انخفاض الحبر).
4. طابعة 4 — Canon الأبيض.
5. طابعة 5 — Canon رصاصي.

هذه تسميات مقترحة؛ إعادة تسمية الطوابير يجب أن تتم على حاسبة المكتبة نفسها. لا تعتمد الطباعة من Epson أو Konica قبل معالجة التنبيهات الظاهرة.

**خيارات افتراضية وليست طابعات المكتبة:** Adobe PDF، Microsoft Print to PDF، OneNote (Desktop)، PDFill PDF&Image Writer.

الأسماء مأخوذة من قائمة الطباعة في Windows ولا تثبت وحدها أن الطابعة متصلة عبر Wi-Fi أو أن الاسم الظاهر هو موديل الجهاز. يلزم تجربة كل جهاز من حاسبة المكتبة وهواتف الموظفين.

## تدفق الطلب

1. يرفع الطالب صورة أو PDF ويحدد المطلوب وعدد النسخ.
2. ينشئ النظام الطلب ورمزًا لمتابعته.
3. يرى الطالب حالة الطلب فقط.
4. يستلم الموظف الطلب والملفات ويحدث الحالة.
5. يضيف الموظف المبيعات والمصروفات اليومية.
6. يراجع المدير التفاصيل المالية وينشئ التقارير.

## الأدوار والصلاحيات

- **طالب:** إنشاء الطلب ومتابعة حالته فقط.
- **موظف:** استلام الطلبات وملفاتها، تحديث الحالة، وإضافة المبيعات والمصروفات.
- **مدير:** إدارة الموظفين، مشاهدة التفاصيل المالية، وإنشاء التقارير.

## نقاط تحتاج قرارًا أو إعدادًا لاحقًا

- أسعار خدمات الطباعة، وهل تُسجل المبيعات يدويًا أم ترتبط بالطلبات المكتملة.
- مقاسات أوراق الطباعة وأبعاد الصور وهوامش الطابعات.
- مدة الاحتفاظ بملفات الطلبات بعد التسليم.
- طريقة استعادة رمز متابعة الطالب عند فقدانه.
- إعداد بيانات قاعدة البيانات والتخزين في إعدادات الخادم فقط؛ لا ترفع مفاتيح أو كلمات مرور إلى GitHub.
- التكامل المباشر مع Telegram أو WhatsApp غير موجود؛ رفع الملفات يعتمد على مشاركة الملفات المتاحة في الجهاز.
- خطة Render المجانية مناسبة للمعاينة فقط؛ يلزم تحديد الخطة الملائمة قبل التشغيل التجاري.

## ملاحظة الجاهزية

وجود الواجهة والخادم في المستودع لا يعني أن الخدمة أصبحت جاهزة للاستخدام الفعلي. يجب إعداد PostgreSQL وSupabase والاستضافة، والتحقق من الصلاحيات وحفظ الملفات، ثم تجربة الطباعة والأجهزة قبل إدخال بيانات حقيقية.
