# خطة مشروع مكتبة الطب

آخر تحديث: 2026-10-26

## المتطلبات المثبتة

| المجال | القرار |
|---|---|
| المستودع | مشروع مستقل باسم medical-library |
| الطالب | يرفع الملفات ويحدد المطلوب طباعته، ثم يرى حالة الطلب فقط |
| الموظف | يستلم الملفات، يتابع الطلبات، ويضيف المبيعات والمصروفات اليومية |
| المدير | يدير حسابات الموظفين وكلمات مرورهم، ويرى التفاصيل المالية ويصدر التقارير |
| الصور | تكرار صورة واحدة أو توزيع صور لأشخاص مختلفين في الصفحة نفسها، بعدد نسخ مستقل لكل صورة |
| التخطيط | إعداد مبدئي 9 صور، 3 أعمدة × 3 صفوف؛ مقاس الورقة والصور قابل للضبط |
| الطباعة | طابعات Wi‑Fi من الحاسبة وموبايلات الموظفين؛ الموديلات ستصل لاحقًا |
| الهاتف | رفع الملفات من الجهاز، ومشاركة الملفات إلى التطبيق حيث يدعم Android والمتصفح ذلك |
| الملازم | مرحلة لاحقة: أقسام وكليات ومراحل وإدارة ملازم |
| الهوية | شعار الكلية سيصل لاحقًا |

## تدفق الطلب
1. يرفع الطالب صورًا أو PDF أو مستندًا ويحدد خدمة الطباعة.
2. ينشئ النظام رقم طلب ورمز متابعة.
3. تظهر حالة الطلب فقط للطالب.
4. يستلم الموظف الطلب وينزل الملفات ويحدث الحالة.
5. يسجل الموظف المبيعات والمصروفات اليومية.
6. يراجع المدير التفاصيل ويصدر التقارير.

## الأدوار
- **طالب:** إنشاء الطلب ومتابعة حالته فقط.
- **موظف:** استلام الطلبات وملفاتها، تحديث الحالة، وإضافة المبيعات والمصروفات.
- **مدير:** إدارة الموظفين وكلمات مرورهم، والتقارير المالية التفصيلية.

## ما يحتاج إعدادًا لاحقًا
- أسعار خدمات الطباعة، وهل يسجل الطلب المكتمل كمبيعة تلقائيًا أم يضيف الموظف المبيعات يدويًا.
- مقاس الورقة وأبعاد الصورة وهوامش الطباعة.
- مدة حفظ الملفات بعد تسليم الطلب.
- طريقة استعادة متابعة الطلب إذا فقد الطالب رمز المتابعة.
- مفاتيح قاعدة البيانات والتخزين تحفظ في إعدادات الخادم فقط، ولا ترفع إلى GitHub.
